# 打开 FizzDeck 时的云端检查

打开 FizzDeck 后，首轮扫描得到 Git 状态和关注名单，就在后台排队检查当前分支的上游。停留在工作台即可看到「云端领先 N 个提交」，同一计数也会出现在体检页。重新激活应用时会为已到期的项目排队；重扫或调整关注会更新名单。切换详情、返回工作台或窗口失焦都不会中断正在进行的获取。

每个项目使用独立的滚动 24 小时限额，按实际开始尝试的时间持久保存，退出再打开仍然有效。跨过午夜不会提前重置。队列一次只处理一个项目；还在等待就被移出关注范围的项目不会消耗限额。失败也计入限额，保留原有的跟踪引用和计数。版本页的手动获取仍可随时使用。

| 范围 | 处理上限 |
| --- | --- |
| L1 云端检查 | 覆盖全部手动关注的 Git 项目；若手动关注不足 8 个，按现有关注策略补入近期活跃项目。第 9 个及之后的手动关注项目同样排队，自动网络并发最多 1。无当前分支或提交的项目跳过。 |
| L0 文件监听 | 持续监听关注排序前 8 个项目根目录的 manifest、锁文件和 `.env*`。命中文件变化只触发该项目的静态检查。 |
| 体检页完整检查 | 每轮最多 8 个关注项目；包含闲置项目时再查最多 8 个闲置项目，逐个执行。两组都优先检查未检查或最久未查的项目。自动打开体检页有 5 分钟冷却。 |

| 远端地址 | 静默模式的条件 |
| --- | --- |
| `https://host/owner/repo.git` | 仅匿名访问。需要 HTTPS 凭据的仓库留给手动同步。 |
| `git@host:owner/repo.git`、`ssh://git@host/owner/repo.git` | 使用系统 OpenSSH 直连同一主机的 22 端口。公有、私有仓库均需原有公钥授权。显式 `:22` 也可用。 |

`host` 仅限 `github.com`、`gitlab.com` 和 `bitbucket.org`。SSH 只接受 `git` 用户；不使用主机别名、跳板、其他端口或协议回退。仓库须有本地跟踪引用和标准 refspec。Git 配置包含自定义命令、include、过滤器、凭据 helper 或未知设置时跳过静默检查。

SSH 要求主机密钥已存在于用户的 `known_hosts` 或系统主机库。未知或已更换的主机密钥会导致本次失败，应用不会接受、添加或更新它。客户端只尝试默认位置 `id_ed25519`、`id_ecdsa`、`id_rsa` 中可直接完成签名的软件密钥；不会询问密码、口令或验证码，不使用钥匙串、SSH agent、硬件令牌或转发。使用自定义 `IdentityFile`、agent 解锁或硬件确认的项目，仍可通过手动同步使用原有配置。

SSH 建连限时 4 秒，整个网络取包限时 8 秒。只请求当前上游分支，不取标签或子模块。对象先进入独立的临时 Git 目录，超过 32 MiB 不导入。核对分支、HEAD、配置和旧跟踪引用后才更新该引用；不拉取合并、不写工作树或 index，不记录远端输出、凭据或密钥内容。
